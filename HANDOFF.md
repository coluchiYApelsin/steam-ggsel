## Что это за проект

Неофициальный плагин Millennium для Steam Store. Он находит открытые предложения GGSEL и вставляет их под оригинальными блоками покупки игры. Нажатие на предложение создаёт собственную страницу товара внутри текущего документа Steam Store. Пока пользователь смотрит товар, адрес остаётся на `store.steampowered.com`, iframe, отдельного окна и новой вкладки нет. Оригинальная страница GGSEL может открыться только после отдельного действия пользователя на этапе перехода к оформлению.

## Текущая архитектура

- **Millennium/Starlight:** `millennium.toml`, `backend/main.lua`, `backend/rpc_functions.lua`, `backend/public_api.lua`. Плагин собирается Starlight в `.star`, содержащий метаданные, Lua backend, frontend и WebKit preload.
- **Запрос предложений:** `webview/preload.ts` определяет AppID и название с текущей страницы, загружает каталог, проверяет его, классифицирует предложения, сопоставляет их с конкретным блоком Standard/Premium/Ultimate и вставляет виджет. Имеются отмена устаревших результатов, повтор и раскрытие дополнительных предложений.
- **Поиск каталога:** `webview/catalog.ts` вызывает публичный поиск категорий GGSEL, рассматривает найденные URL только как кандидатов и сверяет имя корневого каталога. `webview/offers.ts` разбирает JSON/Next.js Flight данные, определяет товар, тип, издание, продавца и условия. Неисполненные данные сайта не вставляются в Steam.
- **Страница товара:** `webview/product-page.ts` временно скрывает и сохраняет исходные узлы магазина, добавляет собственную страницу в `.responsive_page_template_content`, затем восстанавливает DOM и прокрутку. Детали страницы перепроверяются по ID, имени, категории, платформе, типу, изданию и продавцу.
- **Опции и цена:** `webview/options.ts` валидирует существующие варианты товара, их доступность, собирает только настоящие ID выбора и проверяет ответ цены. После изменения выбора прежняя цена очищается; выполняется новый серверный расчёт GGSEL. Перед переходом к сайту GGSEL делается ещё одна проверка. Если сумма изменилась, пользователь видит обе суммы и должен отдельно подтвердить дальнейший переход.
- **Публичный API GGSEL:** `backend/public_api.lua` использует только HTTPS-запросы чтения/поиска к фиксированному `api.ggsel.com`: расчёт цены, отзывы и поиск категории. TLS включён, редиректы выключены, есть таймауты, лимит запросов и ограничение размера ответа. Создание заказов и авторизация не реализованы.
- **CSS:** стили страницы написаны локально для собственного интерфейса Steam. Стили GGSEL через CSP не внедряются.

## Что ещё не закрыто

1. **Проверка передачи параметров на настоящей карточке GGSEL.** В публичном JS сайта найден query-формат `option=option_radio_<ID>_<значение>_...`; плагин строит ссылку с ID, но визуально не подтверждено, что GGSEL применяет выбор при открытии и переносит его в заказ. Документировать как непроверенное до безопасной проверки на шаге до создания заказа. Не отправлять формы заказа и не вызывать `/ecom/buy` или endpoints создания orders.
2. **S.T.A.L.K.E.R. 2:** поиск `api.ggsel.com/elastic/goods/query-categories` по полному имени отдавал чужие категории, по короткому имени — пустой список. Вероятно, нужен иной проверенный public source/category mapping. Не добавлять догадочные алиасы и не ослаблять сопоставление. Для этой диагностики: `diagnostics/search-stalker.ts`, `diagnostics/search-1643320-080.json` (если присутствует).
3. **Языки и локализованные названия в общем случае:** текущая нормализация покрывает регистр, пунктуацию, торговые знаки, апострофы, `&` и сокращения с точками, но общего доверенного Steam↔GGSEL словаря нет. Новые исключения привязывать к проверенному AppID/названию и фактической корневой категории.
4. **Параметры товаров:** для текста и нескольких checkbox значения намеренно не передаются в URL, их нужно выбрать на GGSEL повторно. Несекретные текстовые поля поддерживаются локально; поля с признаками паролей/секретов блокируются. Изменения доставки/состава, если продавец не предоставляет их как отдельную опцию, не реконструируются.
5. Наличие иногда не сообщает остаток (поле `null`); quote подтверждает расчёт для выбранных параметров, но не резервирует товар. Поддерживается только одна единица, не реализован калькулятор количества.
6. Полный браузерный checkout, авторизация, платёжный провайдер и 3DS не тестировались. Плагин лишь показывает настоящую карточку товара по HTTPS после явного подтверждения пользователя.
7. Разбор публичного Next.js Flight и внутренние публичные API не являются стабильным официальным контрактом продавца. При изменении схемы данные должны закрываться с ошибкой, а не отображать старую или вымышленную цену.
8. README сохраняет некоторые пояснения 0.7.0 (например, общий сценарий каталога и прежние live-команды); актуальное описание 0.8.0 находится в `docs/VALIDATION-0.8.0.md`. При следующем изменении синхронизировать README с текущим API и сценариями.

## Сборка на другом компьютере

Основная среда проекта — Windows x64. В исходной среде использовались Node 24.21.0, Bun 1.4.2, TypeScript 5.9.3, `@steambrew/starlight` 1.1.6 и Millennium 3.5.0. Нужен Microsoft Visual C++ Redistributable x64: без `VCRUNTIME140.dll` нативный Starlight ранее завершался Windows-кодом `0xC0000135` (ранее описывался как ошибка 53). Runtime следует устанавливать только с сайта Microsoft.

1. Перенести репозиторий целиком, включая `bun.lock` и тестовые fixtures; установить Git, Node, Bun и C++ Runtime.
2. Из корня выполнить в PowerShell `.\BUILD.cmd`. Скрипт запускает frozen install, TypeScript, тесты, сборку и проверку `.star`.
3. Ручной эквивалент:

   ```powershell
   bun install --frozen-lockfile
   bun run typecheck
   bun test
   bun run build
   ```

4. Результат сборки: `dist/steam-ggsel.star`. Для установки в локальный Millennium выполнить `.\INSTALL.ps1`; перед копированием скрипт сохраняет заменяемый `.star` в `diagnostics/installed-<timestamp>.star`. Для другого пути Steam используется `.\INSTALL.ps1 -SteamPath 'D:\Steam'`.
5. Включить плагин в Millennium, перезагрузить UI/страницу Store. MEP-инструмент разработчика: `bun scripts/millennium-check.ts plugin.status dev.steam.ggselprices` и аналогичные методы `plugin.list`, `plugin.logs`. Работает только на локальном Windows Millennium через MEP named pipe/socket.
6. Для безопасной живой проверки только чтения: `bun scripts/check-options-live.ts` запрашивает публичные страницы/цены товара 5283641; `bun scripts/check-live.ts` проверяет каталог. Эти проверки зависят от доступности GGSEL и сетевого маршрута.

Обычные исходники находятся вне `Program Files`; в Steam устанавливается только `.star`. Не переносить пользовательскую папку Steam, `steamapps`, private diagnostics, Clash-конфигурацию или журналы. Установленный файл на исходной машине: `C:\Program Files (x86)\Steam\millennium\plugins\steam-ggsel.star`; на новом компьютере этот путь может быть другим.

## Важные пути

| Путь | Назначение |
| --- | --- |
| `webview/preload.ts` | Встраивание предложений под Steam purchase blocks, обновление/повтор, открытие страницы товара |
